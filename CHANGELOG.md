# Changelog

## [Unreleased]

### Added

- **Nested Rust module path calls in cross-file data flow** — `api::users::f(...)` now resolves through one nested hop when each module declares the next (`mod api;` + `pub mod users;`), without needing a `use`. Longer chains (`a::b::c::f(...)`) stay unresolved, and an undeclared middle module resolves to nothing. Two paired focused-corpus cases (1 vulnerable, 1 control); corpus is 129 cases at 69 TP / 0 FP / 0 FN / 60 TN. `src/review.rs`
- **Rust `pub use` re-exports in cross-file data flow** — `pub use store::f;` (named, `as` alias, grouped, or a `*` glob, with `crate::`/`self::`/`super::` or bare relative paths) now resolves through one bounded hop: a `use crate::f;` that lands on a re-exporting module binds to the function in the source module. A name offered by two different sources stays unresolved rather than guessed, and chained re-exports are not followed. Two paired focused-corpus cases (1 vulnerable, 1 control); corpus is 127 cases at 68 TP / 0 FP / 0 FN / 59 TN. `src/review.rs`
- **JS/TS re-exports (barrel files) in cross-file data flow** — `export { f } from './x'` and `export * from './x'` in a barrel (`index.js`) now resolve through one bounded hop: an import from the barrel binds to the function in the source module. A name offered by two different glob sources stays unresolved rather than guessed, chains of barrels are not followed, and Rust re-exports (`pub use`) remain unresolved. Two paired focused-corpus cases (1 vulnerable, 1 control); corpus is 125 cases at 67 TP / 0 FP / 0 FN / 58 TN. `src/review.rs`
- **JS/TS default exports in cross-file data flow** — `export default function f` / `export default f` register under the conventional `default` key, and `import f from './x'` (including `import f, { g } from './x'`) binds the local name to it. Anonymous default exports and `import type` lines are skipped rather than guessed. Two paired focused-corpus cases (1 vulnerable, 1 control); corpus is 123 cases at 66 TP / 0 FP / 0 FN / 57 TN. `src/review.rs`
- **Grouped Rust `use` imports in cross-file data flow** — `use crate::store::{find_user, list_users};` now expands to one import per item (`as` aliases and a `*` glob item included), so handlers using the grouped form resolve like the single-`use` form. Nested groups (`use a::{b::{c, d}}`) and re-exports (`pub use`) stay unresolved rather than guessed. Two paired focused-corpus cases (1 vulnerable, 1 control); corpus is 121 cases at 65 TP / 0 FP / 0 FN / 56 TN. `src/review.rs`
- **Multi-line Spring MVC signatures in the data-flow engine** — Java method headers whose annotated parameters sit on their own lines are now parsed (a bounded join of the signature lines; line numbers are preserved), closing the limit the Spring source support documented. Only the parameters an annotation directly marks are seeded, so an unannotated parameter on the same or a following line is no longer tainted by association. Same-file and cross-file resolution are unchanged. Four paired focused-corpus cases (2 vulnerable, 2 controls); corpus is 119 cases at 64 TP / 0 FP / 0 FN / 55 TN. `src/review.rs`
- **Spring MVC and Gin/Echo sources for the data-flow engine** — the shared SQL injection, command injection, and SSRF flow engine now treats framework request reads as taint sources. Java methods with `@RequestParam`/`@PathVariable`/`@RequestBody`/`@RequestHeader`/`@ModelAttribute`/`@CookieValue` parameters are seeded as sources (single-line method headers only; annotation arguments split across lines are not parsed). Go handlers read through gin/echo-style calls: `c.Param`/`Query`/`DefaultQuery`/`QueryArray`/`PostForm`/`DefaultPostForm`/`PostFormArray`/`FormValue`/`QueryParam`/`GetHeader`/`Cookie`, and bind shapes `c.Bind*`/`ShouldBind*`/`ShouldBindWith(&var)` taint the bound variable. Same-file and cross-file resolution are unchanged, so a Spring controller reaching a static service method or a Gin handler reaching a sibling-package store function reports the sink line in the callee. Eight paired focused-corpus cases (4 vulnerable, 4 controls); real projects and mutations are unchanged. `src/review.rs`
- **Same-file and cross-file data flow for Rust** — the shared SQL injection, command injection, and SSRF flow engine now covers `.rs` files. Sources are actix/axum-style request reads (`req.match_info().get(...)`, `req.query_params()`, extractor-map `params.get(...)`/`params[...]`); taint follows `let` aliases and `format!("...{name}...")` interpolation (macro-string `{ident}` arguments stay visible, lifetimes are not mistaken for strings), and `.parse::<i64>()`-style numeric conversions stop the flow. Sinks: `sqlx::query`/`query_as`/`query_scalar` and `conn.execute`/`query`/`prepare`-style receivers for SQL, the single-line `Command::new("sh").arg("-c").arg(cmd)` chain for command injection (argument-vector calls stay clean), and `reqwest`/`ureq` `get`/`post`/... URL arguments for SSRF. Same-file helper calls resolve like the other languages, including `self.` methods. Cross-file, `mod store;` resolves to the sibling `store.rs`/`store/mod.rs` for `store::f(...)` path calls, and `use crate::...`/`self::`/`super::` paths (with `as` aliases or a trailing `::*` glob) resolve from the nearest ancestor holding `main.rs`/`lib.rs`; only `pub` free functions are visible across files, and one import hop is followed. Grouped `use a::{b, c}`, re-exports, and chained `a::b::f(...)` call paths are not resolved. Five paired focused-corpus cases (3 vulnerable, 2 controls); real projects and mutations are unchanged. `src/review.rs`
- **Cross-file import resolution for Java and Go** — the cross-file engine now resolves the import forms PR #40 left out. Java `import static a.b.C.f;` resolves the bare call `f(...)`, `import static a.b.C.*;` resolves every static method of `C` the same way, and `import a.b.*;` resolves every uniquely named class in that package (still static, non-private methods only; a same-name method in the calling class shadows a static import, and a member offered by two classes resolves to neither). Go imports outside the file's own module resolve through `replace` directives that map the module path to a local directory, or through another `go.mod` under the project root whose module path prefixes the import; the module cache and `vendor/` (excluded from scans) are not followed. Ten paired focused-corpus project cases (5 vulnerable, 5 controls); real projects and mutations are unchanged. `src/review.rs`
- **Cross-file data flow for Java and Go** — `review` now follows request input across file boundaries in Java and Go projects. Go files in one directory share a package namespace, so a bare call resolves to a function defined in a sibling file; `import "mod/pkg"` (optionally aliased, single or grouped form) resolves through the module path of the nearest `go.mod`, and only exported (capitalized) names are visible across packages. Java classes in one package refer to each other by class name (`Service.find(...)`), and `import a.b.C;` resolves to the one project file whose package and class name match; only static, non-private methods resolve. A callable name offered by two different files resolves to neither rather than guessing. `import static` and wildcard imports (Java), `_test.go` files, external modules, and calls through instance variables are not followed. The same SQL injection, command injection, and SSRF families, sources, sinks, and sanitizers apply, and one import hop is followed as in JS/TS and Python. Six paired focused-corpus project cases (3 vulnerable, 3 controls); real projects and mutations are unchanged. `src/review.rs`
- **Cross-file data flow for JS/TS and Python** — `review` now follows request input from one project file into functions of another file it imports. Each file's functions are summarized with the same per-parameter pass as the same-file engine, and relative imports are resolved to project files: `require('./x')` / `require('../x')` (including `x/index`), `import * as m` and `import { f as g }` from relative paths, and Python `from .x import f`, `from . import x`, `from x import f`, and `import x as m` resolved next to the importing file or at the project root. A request-tainted argument passed to an exported function in a position that reaches a sink reports the sink line in the imported file (SQL injection, command injection, SSRF). Only exported functions resolve (`module.exports = { ... }`, `exports.x = x`, `export function`, `export { ... }`; Python top-level functions). Package imports, dynamic `require`, default exports, and re-exports are not resolved. One import hop is followed. Java and Go are not covered yet. Four paired focused-corpus project cases (2 vulnerable, 2 controls). The real-project label set gains the three SQL injections upstream declares in `vulnerable-node-api/src/service/index.js` (lines 47, 71, 80). Cipher now reports the two that the controller calls with request input (71, 80). The third (`findUserByName`, 47) has no caller in the snapshot and stays an honest false negative: real projects go from 12/0/0 to 14 TP / 0 FP / 1 FN. `src/review.rs`
- **Same-file interprocedural data flow (JS/TS, Python, Java, Go)** — the shared SQL injection, command injection, and SSRF flow engine now follows calls to functions defined in the same file. Each function gets a parameter-to-sink summary (the same propagation, sinks, and sanitizers, seeded from one parameter at a time), helper chains resolve over bounded rounds, and a request-tainted argument passed in a position that reaches a sink reports the sink line inside the callee. Only bare calls to plain functions (Java: methods of the file) and `this.`/`self.` calls to methods resolve; calls on any other receiver, names defined more than once (overloads, redefinitions), receiver methods in Go, non-simple parameters, and keyword or spread arguments are skipped rather than guessed. The straight-line pass is unchanged. Still same-file only: cross-file calls such as controller → service modules are not followed yet. Ten paired focused-corpus cases (5 vulnerable, 5 controls). `src/review.rs`
- **SSRF rule and data flow (JS/TS, Python, Java, Go)** — new `Server-Side Request Forgery (SSRF)` rule (CWE-918, OWASP A10, `cipher/ssrf`). A narrow same-line pattern catches request input passed straight into an HTTP client call; the shared same-file flow engine follows request input through aliases and string construction into the URL argument of `requests`/`httpx`/`urlopen`, `fetch`/`axios`/`got`/`http(s).get`, `new URL`/`URI.create`/`RestTemplate`, and `http.Get`/`Post`/`NewRequest*`. A request value sent only as a query parameter, body, or header of a fixed URL is not reported. Host allowlists are not treated as sanitizers. Same-file, straight-line only. Eight paired focused-corpus cases (4 vulnerable, 4 fixed-URL controls). `src/review.rs`
- **Command injection data flow (JS/TS, Python, Java, Go)** — `review` now follows request input through local aliases and string construction (the same engine and sources as the SQL injection flow) into calls that hand a command string to a shell: Python `os.system`/`os.popen`/`subprocess.getoutput` and `subprocess` calls with `shell=True`; Node `child_process` `exec`/`execSync`; Java `Runtime.exec` and `ProcessBuilder("sh", "-c", ...)`; Go `exec.Command("sh", "-c", ...)`. Argument-vector process calls without a shell stay clean, and `shlex.quote` or numeric conversions stop the flow. Same-file, straight-line only. Eight paired focused-corpus cases (4 vulnerable, 4 argument-vector controls). The real-project label set gains `python-vuln-demo/main.py:20` (`os.popen`), which upstream marks as intentional command injection and which the original labels missed. `src/review.rs`
- **SQL injection data flow (JS/TS, Python, Java, Go)** — `review` now follows request input (the same sources as the path-traversal models, plus JS destructuring from `req.query`/`req.body`/`req.params`) through local aliases and string construction (concatenation, template literals, f-strings, `format`/`String.format`/`fmt.Sprintf`) into SQL query sinks (`cursor.execute`, `db.query`/`prepare`, `executeQuery`/`prepareStatement`/`createQuery`, `db.Query`/`Exec` and their `*Context` forms). Taint must reach the query argument, so parameterized queries with a request value as a bind parameter stay clean; numeric conversions stop the flow, and identifiers that only appear inside plain string text do not count. Same-file, straight-line only; no interprocedural claim. Eight paired focused-corpus cases (4 vulnerable, 4 parameterized controls). `src/review.rs`
- **GitHub Actions workflow checks** — `review` now scans workflow YAML for untrusted PR-head checkout under `pull_request_target`/`workflow_run`, script injection from attacker-controlled `${{ github.event.* }}` text in `run:`/`script:`, third-party actions not pinned to a commit SHA, `permissions: write-all`, and `toJSON(secrets)`. Nine paired focused-corpus cases (5 vulnerable, 4 clean controls). `src/workflow.rs`, `src/review.rs`

### Changed

- **Position-independent policy fingerprints** — `stable_fingerprint` now keys on rule, file, finding type and the whitespace-normalized flagged line instead of the line number, so unrelated edits no longer re-key accepted baseline findings. Repeated identical findings in one file get ordinal-salted fingerprints so a baseline entry cannot cover a new copy; snippet-less findings keep the line-based key. The committed `.cipher-ai-policy.yml` baseline was regenerated, dropping stale entries. One-time effect: existing baselines, suppressions and GitHub Code Scanning alerts re-key once. `src/finding.rs`, `src/policy.rs`, `src/review.rs`

### Fixed

- **`.github/` was never scanned** — the `.git` exclusion matched by substring, so `.github/workflows` (and `.gitlab-ci.yml`) were silently skipped. `.git` is now matched as a whole path component. `src/scan.rs`
- **`pentest --blackbox` never checkpointed `session.json`** — black-box runs opened a workspace but never saved the session, so `--point-retest` and `--resume` could not find black-box/browser-fuzz findings. The black-box path now persists the full session (stage, guided proofs incl. browser-fuzz specs, findings, summary) before writing the report
- **`pentest --point-retest` of a browser-fuzz proof replayed raw HTTP** — which cannot observe in-browser marker execution, so a sanitizing fix could look `FIXED` while the payload still executed. Browser-fuzz proofs now persist their rendered page + input (`ProofSpec.browser`, serde-back-compatible) and re-test by **re-driving the exact form in headless Chrome** (`exploit::replay_browser_fuzz`): `STILL VULNERABLE` when the marker executes, `FIXED` when it does not, and an explicit "NOT verified as fixed" when no drivable browser exists. The WSL+Windows-Chrome skip path also prints an actionable install/`CIPHER_AI_CHROME` hint (`cdp::browser_unavailable_hint`)
- **TUI `postinstall.js` release version** — binary download version is now derived from `tui/package.json` (was hardcoded to the stale `v0.1.0`, which had no matching release assets), so `npm install` fetches a real binary and stays in sync with future releases
- **CI cross-compile error `can't find crate for core` / `x86_64-pc-windows-gnu target may not be installed`** — `.cargo/config.toml` no longer forces a global `[build] target = "x86_64-pc-windows-gnu"`; `pr-review` and `security-watch` workflows now build with an explicit `--target x86_64-unknown-linux-gnu`. Local Windows-without-MSVC builds can opt in via `cargo build --target x86_64-pc-windows-gnu` or `CARGO_BUILD_TARGET`
- **`cipher-ai report --format html`** — HTML reports now always export to a file (default `cipher-ai-report.html`, or `--output <path>`) instead of dumping raw HTML to stdout; updated CLI help text and TUI descriptions to match

### Added

- **Pentest multi-step attack chaining (Phase 16 / M9.4)** — the pentester reports attack *paths*, not just findings. New `src/pentest/chain.rs`: a deterministic engine derives **primitives** (the capability a proven proof unlocks — mass-assignment user creation, JWT impersonation, SSRF/file-read/command-exec primitives) from guided proofs, then runs a bounded **chained re-sweep** over the endpoints the first pass found **auth-blocked (401/403)**: with the session state the unlock proof established (the shared cookie jar carries it), the dependent finding — e.g. **user-creation → IDOR** — fires only if state actually flipped the auth gate (hop depth ≤ 2, ≤ 8 retests, IDOR/Auth classes only, same validators). The **attack graph** (`build_chains`) links unlock → dependent steps into `AttackChain`s; **continuation agents** — focused, budgeted sub-agents seeded with the achieved state + the chained endpoints — are spawned after the main wave; the Markdown report gains an **Attack Paths** section (steps + endpoints + unlocked capability) while SARIF stays per-finding; chains persist through the workspace checkpoint (`SessionState.chains`) so complete-session re-renders and `--resume` keep them. `[CHAIN]` progress lines + summary narrative, CLI/TUI help updated. 6 `chain.rs` unit tests + 1 integration test (mass-assignment register sets a session cookie → auth-blocked IDOR target is re-probed and proves). `src/pentest/chain.rs` (new), `orchestrator.rs`, `workspace.rs`, `report.rs`, `mod.rs`, `src/main.rs`, `tests/pentest.rs`, TUI components + `dist/index.js`
- **Pentest schema-aware attack surface (Phase 15.3 / M9.3.1)** — the deterministic sweep stops guessing endpoints: it imports the API's own contract. Live `--url` runs **auto-discover** `openapi.json`/`swagger.json`/`/api-docs`/`v3/api-docs` at the target root and **introspect `/graphql`** (and `/api/graphql`) via a `__schema` query into operation skeletons (`query { search(q: "1") }`) the validators can inject into — all probes through the shared session (allowlist + rate limit enforced), silent on failure. Schema targets are swept **first** (a spec is the app's own contract — highest signal) with the sweep cap raised so the contract surface is never starved; **mass assignment** now probes the schema's own body fields (`ExploitSpec.mass_fields`, persisted through `ProofSpec` for point re-test) instead of only the built-in privileged list. Wired into the orchestrator (`with_schema`, `[SCHEMA]` plan line), `--blackbox` (crawl covers HTML, spec covers the API), `--plan-only` (local spec listed with zero requests), and the agent system prompt (schema endpoints injected). 9 `schema.rs` unit tests + 2 integration tests in `tests/pentest.rs` (an explicit spec drives an empty-repo sweep proving SQLi + a mass-assignment proof whose matched field comes ONLY from the schema; auto-discovery finds openapi.json + GraphQL and the merged contract sweep proves both) — plus a negative control proving the spec alone is what found the endpoints. `src/pentest/schema.rs` (new), `exploit.rs`, `orchestrator.rs`, `workspace.rs`, `mod.rs`, `src/main.rs`, `tests/pentest.rs`
- **Pentest deeper proof engine (Phase 15 / M9.3 — beyond Shannon's bug classes)** — the deterministic validator set grows from 7 to **12 classes** and LLM-invented exploits finally enter the pipeline behind a machine oracle:
  - **Five new deterministic validators** in `exploit.rs`: **JWT** (token located in an `Authorization: Bearer` header or `token`/`jwt` param; baseline garbage token must be rejected, then `alg: none` unsigned admin token or an **HS256 token signed with a guessed weak secret** — via new `sha2` dep + hand-rolled RFC 4648 §5 base64url — flips the rejection), **mass assignment** (POST/PUT/PATCH JSON body accepts an unexpected privileged field — `role`/`admin`/`is_admin`/… — and reflects it back), **SSTI** (template expressions `{{a*b}}`/`${{…}}`/`#{…}`/`${…}`/`<%…%>`/`[[…]]` evaluated server-side: the *product* appears while the raw expression does not), **NoSQL injection** (JSON operator wraps `$ne`/`$gt`/`$regex` flip an auth check, grow the response, or surface Mongo/JS error markers; top-level `$where` probe), **XXE** (XML external entity → outbound **callback listener** — the SSRF accept-race pattern — plus `file:///etc/passwd` read reflection). Same evidence discipline: payloads + observed responses only; POST-gated classes bail on GET, so the clean-target suite stays green
  - **`propose_exploit` oracle gate** (the 15.2 milestone) — a new agent tool for classes with **no deterministic validator** (business logic, authz races, GraphQL): the agent drafts canonical (baseline) vs mutated (exploit) inputs plus an `expected_marker`; the deterministic **oracle** (`oracle_gate`) replays BOTH through the shared session and **ACCEPTS the PoC only on an observable differential** — status flip (401→200 / →500), body growth > 200 bytes, body change, or the marker observed. No differential / no marker → `Oracle REJECTED` and no finding — the "no exploit, no report" rule holds for LLM-invented exploits. Accepted proofs become `BusinessLogic` findings (or the agent's chosen class) at 0.6 confidence with both request/response pairs in evidence. The tool is scope-gated and honors `vuln_classes` restrictions; `exploit`'s schema/error/summary now list all 12 classes
